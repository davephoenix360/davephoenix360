## What This Project Is

Diepreye's **GitHub profile README** at `davephoenix360/davephoenix360`. Theme: **retro arcade / CRT / pixel aesthetic**.

## Constraints (the GitHub README reality)

- **No build step** — what you write in `README.md` is what GitHub renders
- **GitHub strips `<style>` and `<link>` tags** at the top of READMEs (CSS renders as visible raw text)
- The aesthetic here uses **typing-SVG widget + Unicode box-drawing** for the visual style — no inline CSS, no embedded stylesheets
- Everything else falls back to default GitHub markdown styling (clean + readable)

## File Layout

```
profile-redesign/
└── README.md       # The profile README (single source of truth)
```

That's it. No `package.json`, no `node_modules`, no build pipeline.

## Visual Architecture

- **ASCII art** at the top: "DAVE" rendered in box-drawing characters
- **WAVE 1 — DEFEND THE CONTRIBUTION GRAPH**: an animated SVG (`commit-invaders-dark.svg`) hosted at `https://raw.githubusercontent.com/davephoenix360/davephoenix360/output/...`
  - Real **Space Invaders game** driven by the user's last 365 days of commits
  - Each commit = 1 invader; each day of code = 1 laser shot
  - Pure CSS animation, **updated daily at 00:00 UTC**
- The SVG file lives on a separate `output` branch and is regenerated by a daily cron / GitHub Action

## DO

- Keep `README.md` self-contained (no external scripts, no JS)
- Use **typing-SVG** or Unicode box-drawing for visual style
- Test that SVG images still load (the `output` branch must be in sync)
- Verify `<img>` tags use absolute URLs (`https://raw.githubusercontent.com/...`) — relative paths don't work
- Use descriptive `alt` text for images (accessibility)
- Keep total README size reasonable (GitHub has implicit size limits)

## DON'T

- Don't add `<style>`, `<link>`, or `<script>` tags — GitHub strips them
- Don't use relative image paths — they break on the profile render
- Don't add features requiring JS execution (GitHub strips most JS too)
- Don't commit the SVG output files to `main` — they live on the `output` branch
- Don't add a build pipeline — there's no need

## Editing Workflow

1. Edit `README.md` in this repo
2. If changing the SVG widget:
   - The SVG source / generator likely lives elsewhere (check GitHub Actions, or the `output` branch)
   - The `output` branch is what `raw.githubusercontent.com` serves
3. User commits and pushes to `main`
4. The profile README updates within ~1 minute

## Common Tasks

| Task | Where |
|---|---|
| Change ASCII art | Edit top of `README.md` |
| Change WAVE 1 SVG | Regenerate via the SVG generator (not in this repo) + push to `output` branch |
| Change text content | Edit body of `README.md` |
| Add a new section | Append to `README.md` using markdown |

## Anti-Patterns

- Don't use HTML `<style>` blocks
- Don't use relative image paths
- Don't use animated GIFs (too heavy — use SVG animation instead)
- Don't try to add interactivity via JS
